“I have multiple services that need to run together. Docker Compose lets me define the services, networks, ports, database, restart policies, and dependencies in one configuration and start the environment with a single command.”

4. Why Prometheus?

“Prometheus is used for monitoring and collecting time-series metrics. My services expose metrics such as order failures and payment failures, and the Incident Manager queries Prometheus to detect abnormal behavior.”

Your actual detection query:

5. How does your system detect an incident?

“The Incident Manager periodically queries Prometheus. When the failure rate crosses the configured threshold, it creates an incident. I also use edge-triggered suppression so the same continuously active failure condition does not create duplicate incidents.”

That's an important advanced detail.

8. What is the circuit breaker?

This is important.

“A circuit breaker prevents a service from continuously calling a failing dependency. When failures exceed a threshold, the circuit can open and temporarily stop requests to the dependency. This helps prevent cascading failures.”

Simple example:

Order Service
     ↓
Payment Service ❌
     ↓
Repeated failures
     ↓
Circuit opens
     ↓
Stop unnecessary calls
9. Why do you need retries if you already have a circuit breaker?

Good professor question.

“They solve different problems. Retry handles temporary failures by attempting the request again. Circuit breaking protects the system when failures become persistent. Using both provides better resilience.”

10. Why do you need a timeout?

“Without a timeout, the Order Service could wait indefinitely for the Payment Service. A timeout bounds how long the request can consume resources.”

Your system uses approximately:

Order → Payment timeout = 2 seconds

So when Payment takes 5 seconds:

Payment latency = 5s
Order timeout = 2s

5s > 2s
   ↓
Order request fails

No.

This is one of your strongest answers.

“No. The LLM only diagnoses and recommends. A deterministic safety policy evaluates the actual evidence and decides whether a predefined action is allowed.”

Your system does:

20. Is this really "self-healing"?

If your professor challenges you:

“Docker can restart a container. Why are you calling this self-healing?”

Don't say Docker itself is your invention.

Say:

“Docker provides the container restart capability, but the self-healing workflow is broader. My system detects the incident through observability, collects evidence, uses GenAI for diagnosis, applies a safety policy, selects an approved recovery action, executes it, verifies recovery, and records the complete incident lifecycle.”

That's a much stronger answer.

The question you should be especially prepared for

Answer:

“Kubernetes already provides infrastructure-level self-healing such as restarting failed containers. My project is exploring a different layer: using GenAI to assist with incident diagnosis while keeping automated recovery behind deterministic safety policies. So the project is not claiming to replace Kubernetes; it explores an AI-assisted incident response layer.”

Excellent answer for a professor.
